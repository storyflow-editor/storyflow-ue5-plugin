##### New Features

- **Blueprint access to `FStoryFlowVariant`**: values the plugin hands out as variants were dead ends in Blueprint - the struct's fields are private with C++-only getters, so the Character Variables map on the dialogue state, `GetArrayVariable` and `GetMapVariable` elements and the legacy `GetCharacterVariable` all returned something you could hold but not read. `UStoryFlowVariantLibrary` adds pure nodes under `StoryFlow|Variant`: `IsValid` and `GetType`, typed `GetVariantAs` Bool/Int/Float/String readers with default pins (delegating to the same C++ getters, so int to float coercion and string-family handling match the runtime), a display string for debugging, array and map readers (maps come back as parallel Keys and Values arrays in the editor's serialized order) and `MakeVariantFrom` constructors for the variant-taking APIs. Two things to know when reading the dialogue state's Character Variables map: keys are the variable display names exactly as authored in the editor's character panel, and the built-in Name and Image are not in that map - they stay on their dedicated fields

##### Bug Fixes

- **Array outputs from called scripts arrived empty**: a script output of an array type reached the calling script as an empty array through the Run Script node, while scalar outputs and direct global array reads worked. The array input resolver never looked at Run Script sources, so the wire fell through to the it-must-be-a-variable path and returned nothing. The resolver now maps the wired output to the called script's stored result the same way the scalar reads do. Thanks to Jonatan Nielsen for finding and fixing this one
- **Character variable nodes lost their variable name with a dynamic character**: `getCharacterVar` and `setCharacterVar` resolved the character correctly when it arrived through the input pin, but the variable name came in empty, so the read or write did nothing. The importer only parsed the variable name when a character was embedded in the node, and a dynamically supplied character has no embedded path. The name is now parsed regardless. Existing projects reimport once on the next sync so already-imported nodes pick up the fix - under revision control that sync checks out the StoryFlow folder, which is expected. Thanks to Jonatan Nielsen for this fix as well
- **For Each loop elements in option conditions always hid the option**: a boolean loop element wired directly into a dialogue option's condition evaluated false no matter the element, so the option never appeared, and a comparison on an int, float or string loop element used as a condition had the same problem one step removed. The current element lived only in the evaluation cache, and entering a dialogue clears that cache right before option visibility is computed. Loop element reads now resolve from the loop's own persistent state, which survives the clear - the same storage For Each Map's key and value reads already used
