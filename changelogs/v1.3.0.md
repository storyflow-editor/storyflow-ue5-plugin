##### New Features

- **Data Assets Import With the Project**: A full StoryFlow Editor export brings in `.sfd` Data Assets as Unreal assets, including assets used only from game code. Parent links, authored overrides and referenced images or audio come with them. Reading a child uses the nearest value in its parent chain; changing a parent value during play reaches descendants that have not overridden it

- **Data Asset Nodes in Dialogue Graphs**: Get Data Asset, Get Data Asset Variable and Set Data Asset Variable nodes now execute in Unreal. The reference node chooses the asset for connected accessors, and a boolean value can gate a dialogue option. Array operations wired through an accessor update the runtime value rather than rewriting the imported asset

- **Blueprint and C++ Access to Data Assets**: `UStoryFlowComponent` and `UStoryFlowSubsystem` expose typed getters and setters for bool, int, float, string and enum values. Find Data Asset accepts a stable ID or an unambiguous display name, while Get Data Asset Variable Names lists declarations from the parent chain. Variant access reads arrays and maps; container setters replace declared arrays and maps with type-checked values. These calls are available to game systems that have no active dialogue

- **Data Asset Changes in Save Slots**: Writes made during play are stored with the story state and restored by loading a slot. The imported Data Asset remains unchanged. Reset Data Asset Overlay clears the session's writes and returns reads to the authored values

- **Stable Character IDs**: Current StoryFlow Editor exports include an index connecting each character ID to its imported record. Dialogue nodes prefer that ID, and `GetCharacterById`, `GetCharacterVariableById` and `SetCharacterVariableById` let Blueprints and C++ keep a character binding when its file moves or is renamed. Existing path-based APIs and exports without an index continue to work

- **Project-Wide Localization**: Import `localization.json` to resolve authored dialogue, option text, character names and declared Data Asset strings in the selected language. `UStoryFlowSubsystem` provides Get Languages, Get Language, Set Language and an On Language Changed event for a game's language menu. New reads use the new language; a dialogue line already on screen keeps its resolved text until the game advances. Save slots do not store the player's language preference

- **Audio-Driven Lip Sync**: Add `UStoryFlowLipsyncComponent` to a character actor, bind it to a StoryFlow dialogue source and set the speaking character ID. It analyzes the playing voice and drives existing ARKit-style facial morph targets without precomputed phoneme tracks. The built-in mapping supports Synty Sidekick faces, including separate head, teeth and tongue meshes under Face Root. A `UStoryFlowVisemeMap` can use different morph names and weights, while strength, sensitivity, jaw bias and smoothing tune the response. A dedicated Analysis Submix keeps music and effects out of the mouth movement. Direct MetaHuman support is planned for a later update

##### Improvements

- **Data Asset Media Is Available Outside Its Source Script**: Images and audio referenced by a Data Asset join the project asset pool, so a different dialogue or Blueprint can still resolve them

- **Variable Names Can Be Read at Runtime**: Get Data Asset Variable Names returns the names declared along an asset's inheritance chain, including inherited entries, for menus and tools that should not hardcode every field

- **Lip Sync Tracks the Face and the Audio**: The component can re-find facial meshes replaced during play, keep analyzing while the line's audio continues and return the mouth to rest when that audio stops. `GetLevel()` and `GetRawPeak()` help tune the analysis against a voice recording

- **Character APIs Reject Stale Types**: A character-variable node whose saved type no longer matches the current declaration refuses the write instead of replacing a valid value with a mismatched one

##### Bug Fixes

- **Array Operations Keep Their Results**: An array operation through a Data Asset accessor no longer erases its own output, and Set Array Element works again when it is wired into a story graph

- **Dialogue Options Recheck Data Asset Changes**: Writing a Data Asset boolean from Blueprint invalidates the relevant condition result, so options do not continue to use an earlier answer

- **Data Asset State Survives Repeated Writes and Restores**: Runtime reads, saves and loads keep the session's current values rather than holding a stale copy after a later write or project update

- **Dialogue Activity Clears When It Ends**: A stopped or torn-down dialogue releases its active state, so a later save load is not refused as though an old conversation were still running

- **Localized Reads Do Not Change Runtime Names**: Switching language resolves authored text without rewriting character or variable identifiers that game logic still needs to look up

- **Lip Sync Stops With Playback**: The mouth closes when the line's sound stops, and face or dialogue lifecycle changes no longer leave an old analysis running

##### Notes

- **Unreal Engine 5.8 Packaged Morphs**: Desktop packages in Unreal Engine 5.8 need **Use GPU for computing morph targets** enabled in the project's Rendering settings. Without it, audio analysis can run while cooked facial morph targets remain still
